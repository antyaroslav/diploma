# Результаты проверки «Мобильного хосписа»

## Исходная проверка интерфейса

21.10.2026 проверялся debug `1.0.0` (`14`) на Android 16 / API 36,
x86_64, Pixel 6, 1080×2400, en-US, Europe/Moscow. Сборка на
AGP 8.12.2 / Gradle 8.13 завершилась успешно. Выполнена интерактивная проверка UI;
отдельный замер длительности исходного прогона не проводился.

Из 64 исходных сценариев: 31 пройден, 1 не пройден, 2 заблокированы,
30 не выполнены полностью. Исторические статусы сохранены в
[Check.xlsx](Check.xlsx) / [Check.md](Check.md) и [Cases.xlsx](Cases.xlsx) / [Cases.md](Cases.md).
Новый UI-прогон отражён отдельным полем кейсов и не подменяет эти результаты.
Снимки исходной проверки находятся в `docs/evidence/stage1/`.

## Итоговый UI-прогон

22.10.2026 выполнены восемь независимых Espresso-тестов на API 36:
**7 пройдено, 1 не пройден**. Единственный сбой —
`NewsRegressionTests.creationDateEqualsToday`, связанный с BUG-001 в [Bugs.xlsx](Bugs.xlsx).
Сбой подтверждён assertion failure и снимком интерфейса. Корневая причина
на стороне клиента или сервера не установлена; инфраструктурных сбоев
в итоговом прогоне нет. Исполняемый шаг сравнения даты в Allure имеет статус `failed`,
очистка собственной новости — `passed`. Поведение приложения ради теста не менялось.

Отчёт: [allure-results.zip](allure-results.zip),
[сводка прогона](docs/evidence/stage2/summary.json),
[снимок BUG-001](docs/evidence/stage2/BUG-001-creation-date.png).
Отчёт содержит восемь результатов, шаги, метаданные тестов и вложение для сбоя.
Gradle/Python runner возвращают код `1` из-за зарегистрированного дефекта.

В итоговом автопрогоне при ожидаемой дате `22.10.2026` отображается `25.08.58777`.
Дополнительный пошаговый UI-прогон подтвердил тот же дефект с другим ошибочным значением `22.08.58777`:
[снимок повторной проверки](docs/evidence/manual-run/creation-date-defect.png).
Ошибочная дата зависит от создаваемой записи; дефект не сводится к постоянному значению.
Полный отчёт с шагами, серьёзностью и приоритетом находится в Bugs.xlsx.

Набор покрывает авторизацию, выход, создание новости, неполный диапазон дат,
восемь цитат и раскрытие первой карточки. Отдельного экрана «О приложении»
в навигации предоставленной версии нет; цитаты находятся в Our Mission / «Наша миссия».
TC-003, TC-036, TC-041, TC-055 и TC-058 автоматизированы частично;
точные границы и методы указаны в Cases.xlsx. Очистка в teardown не является
отдельным полным прогоном TC-055. Весь чек-лист этими восемью тестами не покрывается.

## Ручной прогон и сравнение времени

**Время ручного прохождения человеком пока не измерено.** Сохранённый замер
302,344 с относится к пошаговому UI-прогону с программным вводом данных и управлением
эмулятором. Он подтверждает длительность этих действий, но не скорость ручной работы
тестировщика. Для окончательного сравнения нужен отдельный ручной замер.

Методика предварительного UI-замера: пошагово через интерфейс эмулятора, без запуска Espresso-тестов.
Замер `time.monotonic` включает подготовку исходного состояния, ввод данных,
ожидания, управление эмулятором, фиксацию результатов и очистку собственных новостей.
У каждого сценария сохранены UTC-начало/конец, монотонные отметки, шаги и снимки:
[журнал замеров](docs/evidence/manual-run/timings.json).
Интервалы между сценариями исключены. Подготовка, проверка результата и фиксация
доказательств входят в длительности вместе с действиями; отдельного времени каждого
из этих этапов журнал не содержит.

В обоих прогонах рассматриваются выбранные восемь сценариев, однако способы
проверки и накладные действия отличаются. Например, пошаговый прогон включает
прокрутку и просмотр восьми цитат, а автотест проверяет заголовок и количество
элементов адаптера; снятие доказательств также занимает разное время.
Оба прогона включают подготовку сессии и очистку собственных записей.
Для частичных кейсов сопоставляется только реализованная часть.
В пошаговом UI-прогоне **7 пройдено,
1 не пройден (BUG-001)**; созданные три собственные новости удалены, чужие сохранены.

Предварительный UI-прогон выбранной восьмёрки занял **5 мин 2,344 с**.
Сумма длительностей тестов Allure — **1 мин 9,608 с**.
Разница измеренных длительностей — **232,736 с**. Это сравнение двух способов
управления интерфейсом; оно не подтверждает экономию относительно ручного
прохождения человеком. Процент ускорения ручной проверки до её замера не рассчитывается.

Полный запуск Python runner с Gradle занял **83,578 с**. С учётом этих накладных
расходов разница с предварительным UI-замером составляет **218,766 с**.
Сумма длительностей сценариев и полное время запуска показаны отдельно,
поскольку сборка/установка и работа runner не равны исполнению тестов.

Перед повторными замерами были две подготовительные попытки:

| Попытка | Время, с | Причина отдельного учёта |
| --- | ---: | --- |
| TC-002, первая попытка | 180,390 | Исправление чтения временного журнала при подготовке |
| TC-041, первая попытка | 357,844 | Исследование выбора категории, отмена формы и повтор ввода |
| **Итого подготовка** | **538,234** | Сохранена в exploratory_attempts журнала замеров |

Для сравнения TC-002 и TC-041 повторены по известным шагам; использованные повторы
помечены `repeated_after_preparation`. Подготовительные попытки сохранены и не включены
в 302,344 с. Сумма всех измеренных пошаговых UI-попыток — **840,578 с**; она включает
подготовку и повторение сценариев, поэтому не сравнивается напрямую с одним автопрогоном.
Затраты на разработку/отладку автоматизации отдельным таймером не измерялись
и в сравнение длительностей не входят.

Для завершения ручного сравнения выполнить те же восемь сценариев самостоятельно
через экран эмулятора с вводом данных с клавиатуры и нажатием элементов мышью.
Перед измерением ознакомиться с шагами. Засекать каждый сценарий от подготовки
сессии до проверки результата и очистки собственных данных; отдельно записывать
время подготовки до прогона и оформления отчёта после него. Зафиксировать исход,
длительность и дату каждого сценария. Затем сопоставить сумму с 69,608 с исполнения
автотестов и отдельно с 83,578 с полного запуска. До этого требование о сравнении
ручного и автоматизированного тестирования выполнено частично.

## Ограничения

Проверен один эмулятор API 36 и один итоговый запуск восьми тестов; серия повторов
для оценки разброса времени не проводилась. Общий учебный backend и сеть влияют на время.
Отдельная роль без admin, TalkBack, полная визуальная проверка и все варианты
локалей/шрифтов остаются за пределами выполненного набора.
Очистка собственных новостей подтверждена для сохранённых прогонов. Случай потери
ответа после успешного создания на сервере не проверялся: если запись отсутствует
в текущем списке панели, teardown её пропускает. Для такого сбоя требуется повторно
проверить собственные записи; гарантии удаления при любой сетевой ошибке нет.
Вывод об ускорении относительно ручной работы требует отдельного ручного замера.
