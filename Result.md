# Результаты проверки «Мобильного хосписа»

## Расширенный прогон 26.10.2026

Набор расширен с восьми до **32 UI-тестов**: **27 пройдено, 5 не пройдено**.
Пропущенных тестов и результатов со статусом `broken` нет. Все пять падений
связаны с четырьмя подтверждёнными дефектами; два сценария воспроизводят BUG-003.
Сумма длительностей тестов — **278,601 с**, полный запуск со сборкой и установкой — **292,625 с**.

Окружение: debug `1.0.0` (`14`), Android 16 / API 36, x86_64, Pixel 6,
1080×2400, en-US. Фактическая настройка часового пояса этого запуска — GMT / UTC.
Использованы AGP 8.12.2, Gradle 8.13 и JDK 17;
[параметры окружения](docs/evidence/expanded-2026-10-26/environment.json) сохранены отдельно.
Тёмная тема приложения включается
для соответствующих тестов; прежний режим восстанавливается после сценария.

Доказательства: [Allure](allure-results.zip),
[сводка полного запуска](docs/evidence/expanded-2026-10-26/summary.json).
Отчёт содержит фактические статусы, длительности, исполняемые шаги и вложения.
Gradle и Python runner возвращают код `1` из-за неуспешных регрессионных проверок.
Ожидаемые результаты не подменялись фактическими ради успешного завершения сборки.

BUG-003 — сохранённые дата и время при подтверждении диалогов;
BUG-004 — доступность опубликованной новости после навигации.

Количество дефектов не следует приравнивать к количеству упавших тестов.

Переходы между Главной, Новостями, Панелью управления и Нашей миссией проверяются
точными маркерами соответствующих экранов. Отдельная регрессионная проверка
зафиксировала потерю доступа к созданной записи после перехода между разделами.
Исчезновение карточки из интерфейса само по себе не доказывает удаление на backend.

Для независимых проверок редактирования и удаления фабрика данных выбирает будущую
публикацию через десять лет; изменение даты использует одиннадцать лет.
Проверка доступности опубликованной записи отдельно использует текущую дату и `00:01`.
Так сценарии CRUD отделены от сценария воспроизведения BUG-004 в исследованном
состоянии общей ленты. Это не гарантирует одинаковое наполнение любого backend.

Все шаги очистки в итоговом прогоне завершились успешно: удалены 12 собственных
записей, 11 через UI и одна резервной командой. Сначала удаляются видимые
собственные записи через UI по точным заголовкам. Для созданной записи запоминается ID
из карточки. Резервная очистка вызывает существующую команду удаления приложения
только для зарегистрированных собственных ID, которые ещё не удалены сценарием;
так удалена и недоступная в списке запись сценария BUG-004.
Пользовательские действия и проверки остаются UI-сценариями.
Неподтверждённое сохранение без полученного ID и ошибка очистки отражаются в отчёте;
ошибка очистки не заменяет исходную причину падения теста.

Кейсы и чек-лист представлены только в Excel: [Cases.xlsx](Cases.xlsx) и
[Check.xlsx](Check.xlsx). Исходные 64 результата сохранены как история проверки.
Новые строки TC/CHK-065–088 содержат результаты с указанием источника `(UI)`.
Покрытие исходных кейсов UI-тестами и его ограничения указаны отдельно в Cases.xlsx.

## Ручной прогон и сравнение времени

**Время самостоятельного ручного прохождения человеком пока не измерено.**
Журнал 22.10.2026 содержит предварительный пошаговый UI-замер с программным вводом
и управлением эмулятором: [timings.json](docs/evidence/manual-run/timings.json).
Восемь выбранных сценариев заняли **302,344 с**. Две подготовительные попытки
заняли **538,234 с** и учтены отдельно; сумма всех измеренных попыток — **840,578 с**.
UTC-отметки, монотонные интервалы, действия и снимки сохранены в журнале.

Этот замер включает подготовку сессии, ввод, управление эмулятором, наблюдение,
фиксацию результатов и очистку собственных данных. Межсценарные интервалы исключены.
Он подтверждает длительность конкретных действий, но не скорость работы человека.
Например, пошаговая проверка цитат включает прокрутку и просмотр карточек, а автотест
проверяет заголовок и количество элементов адаптера. По этим числам нельзя делать
вывод об экономии времени относительно ручной проверки человеком.

Предварительные восемь сценариев нельзя сравнивать с новым набором из 32 тестов
как равные объёмы. Для окончательного сравнения выполнить вручную тот же выбранный
набор и те же проверки, предварительно изучив шаги. Отдельно измерить подготовку,
прохождение от исходной сессии до проверки результата и очистки данных, затем
оформление отчёта. Зафиксировать длительность и исход каждого сценария.
До такого замера требование сравнения ручного и автоматизированного тестирования
выполнено частично. Затраты на разработку и отладку отдельным таймером не измерялись.

## Ограничения

Проверен один эмулятор API 36; серия запусков для статистической оценки времени
не проводилась. Общий backend, его наполнение и сеть влияют на результаты.
TC-087 требует хотя бы одну существующую опубликованную новость в общей ленте.
Поведение полностью пустого backend этим сценарием не подтверждается.
Новые кейсы расширяют покрытие, но не заменяют весь чек-лист автоматизацией.
Отдельная роль без admin, TalkBack, полная визуальная проверка и все варианты
локалей и размеров шрифтов остаются за пределами выполненного набора.
Недоступность backend или неизвестный результат сохранения не позволяют гарантировать очистку данных.
