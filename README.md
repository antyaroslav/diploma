# Мобильный хоспис — UI-тестирование

Android-приложение и дипломный проект тестирования. Тесты используют Kotlin,
Espresso, Page Objects, JUnit4 и Allure Android.

## Документация

- [План проверки](Plan.md).
- [Чек-лист](Check.xlsx).

- [Отчёты о дефектах](Bugs.xlsx).

Статусы исходной интерактивной проверки UI и результаты UI-тестов учитываются раздельно.
В новых проверках источник автоматического результата обозначен пометкой `(UI)`.

## Окружение

- JDK 17 и Android Studio.
- Python 3.10+ для `scripts/run_ui_tests.py`; Allure CLI для просмотра результатов.
- Android SDK Platform 36 и Platform Tools; Gradle Wrapper 8.13,
  Android Gradle Plugin 8.12.2 (версии заданы проектом).
- Выделенный эмулятор Android 16 / API 36, рекомендованы Pixel 6,
  x86_64, en-US, Europe/Moscow, корректная текущая дата.
- Интернет для загрузки зависимостей и доступа к учебному backend.

Открыть корень проекта в Android Studio, дождаться синхронизации и создать
эмулятор API 36 через Device Manager. Путь SDK задаётся Android Studio
в `local.properties` либо переменной `ANDROID_HOME`.

Команды сборки в PowerShell из корня репозитория:

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest
```

На macOS/Linux использовать `./gradlew` с теми же задачами.

## Запуск и отчёт

Создать локальный файл `qa-local.properties` (он указан в `.gitignore`) с полями
`qaLogin` и `qaPassword`, заполнив их учебными данными из задания. Альтернатива —
переменные окружения `QA_LOGIN` и `QA_PASSWORD`.
Gradle передаёт значения runner через instrumentation arguments. Не добавлять
значения в команды, исходники, скриншоты и отчёт.

Запустить выделенный эмулятор, проверить его serial командой `adb devices`.
Единый запуск с извлечением и упаковкой результатов Allure:

```powershell
python scripts/run_ui_tests.py --serial emulator-5556
```

Отдельный сценарий можно запустить с фильтром класса и метода:

```powershell
python scripts/run_ui_tests.py --serial emulator-5556 --class ru.edu.qamid.diploma.tests.NewsDeleteTests#confirmedDeletionRemovesNewsAfterReload
```

Такой запуск заменяет корневой архив результатами выбранного сценария. Перед передачей
итогового отчёта выполнить полный запуск без `--class`.

Непосредственный запуск instrumentation-тестов:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest -Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true
```

Runner: `io.qameta.allure.android.runners.AllureAndroidJUnitRunner`.
Флаг `leaveApksInstalledAfterRun` сохраняет APK и внутренний каталог Allure после
прогона. Основной Python runner задаёт этот флаг и извлекает результаты автоматически;
при прямом запуске Gradle выгрузка архива сама не выполняется.
32 теста находятся в пакете `ru.edu.qamid.diploma.tests` и разделены по функциям:
`AuthTests`, `DarkModeTests`, `NavigationTests`, `NewsTests`, `NewsEditTests`,
`NewsDeleteTests`, `MissionTests`, `NewsRegressionTests`.
Действия и проверки элементов выполняются в Page Objects пакета `pages`.
Статические локаторы хранятся в полях, карточки собственных новостей выбираются
динамическими локаторами с точным уникальным заголовком.
DTO `Credentials`, `NewsDraft`, `DateRange`, `OwnedNews` и фабрика `TestData` находятся в пакете `data`;
подготовка сессии и очистка — в `support`. Связь с кейсами и границы частичного
покрытия представлены в Cases.xlsx.

Набор проверяет вход и выход из разных разделов, пустой вход, авторизацию в тёмной теме
и читаемость введённого логина, навигацию через меню и Back, создание, редактирование, отмену
изменений и удаление собственных новостей, неполный диапазон дат, восемь карточек
цитат и раскрытие первой карточки, дату создания и сохранение даты/времени в диалогах
редактирования. Также проверяются смена активности, сброс пустого фильтра и доступность
созданной опубликованной новости после перехода между разделами.
Отдельного экрана «О приложении» в этой версии нет.
На общем backend изменяются только собственные новости с уникальным префиксом
`QA_DIPLOMA_`; очистка удаляет их после сценария.
Для независимых проверок редактирования и удаления используются собственные записи
с будущей публикацией: основная фабрика выбирает дату через десять лет, изменение
даты — через одиннадцать лет. Проверка доступности опубликованной новости отдельно
использует текущую дату и время `00:01`. Конкретные варианты описаны в Cases.xlsx.

Очистка восстанавливает панель и удаляет видимые записи по зарегистрированным точным
заголовкам, включая исходный и изменённый заголовки. После создания запоминается
серверный ID из карточки. Если собственная запись отсутствует в загруженной части
списка, резервная очистка вызывает существующую команду удаления приложения только
для этого ID. Уже подтверждённо удалённые записи повторно не удаляются.
Сценарные действия и проверки выполняются через UI; резервная команда используется
только для очистки данных. Ошибка очистки сохраняется в отчёте и не скрывает первичную
причину падения. Если результат сохранения неизвестен и ID получить не удалось,
очистка отмечается как неподтверждённая. Недоступный backend не позволяет гарантировать удаление.

Регрессионные проверки сохраняют правильные ожидания: текущую дату создания,
читаемый текст авторизации, сохранённые значения даты/времени и доступность созданной
новости. При воспроизведении зарегистрированных дефектов эти проверки падают.
Причину каждого сбоя проверять по Allure и [Result.md](Result.md); любое другое падение
требует отдельного разбора. При неуспешных тестах Gradle и Python runner возвращают код `1`.

Сохранённый полный прогон 26.10.2026: **27 passed, 5 failed**, четыре зарегистрированных
дефекта. Две проверки даты и времени относятся к одному BUG-003. Подробности и
доказательства находятся в Result.md и Bugs.xlsx.

Скрипт использует `adb` из `ANDROID_HOME`, `ANDROID_SDK_ROOT` или `PATH`.
При единственном авторизованном устройстве API 36 параметр `--serial` можно опустить.
Результаты выгружаются и при падениях тестов: архив `allure-results.zip` в корне
содержит каталог `allure-results/`. Лог сборки/прогона находится в
`build/qa-run/gradle.log`, сводка — в `build/qa-run/summary.json`.
Ненулевой код возврата сохраняется при ошибках Gradle или извлечения отчёта.

Для просмотра распаковать архив и открыть каталог результатов через Allure CLI:

```powershell
allure serve allure-results
```
